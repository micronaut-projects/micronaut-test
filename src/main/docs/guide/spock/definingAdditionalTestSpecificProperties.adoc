You can define additional test specific properties using the `@Property` annotation. The following example demonstrates usage:

snippet::io.micronaut.test.spock.PropertySpec[project="test-spock", language="groovy", title="Using `@Property`"]

Note that when a `@Property` is defined at the test method level, it causes a `RefreshEvent` to be triggered which will update any `@ConfigurationProperties` related  to the property.


Alternatively you can specify additional `propertySources` in any supported format (YAML, JSON, Java properties file etc.) using the `@MicronautTest` annotation:

snippet::io.micronaut.test.spock.PropertySourceSpec[project="test-spock", language="groovy", title="Using `propertySources` stored in files"]

The above example expects a file located at `src/test/resources/io/micronaut/test/spock/myprops.properties`. You can however use a prefix to indicate where the file should be searched for. The following are valid values:

* `file:myprops.properties` - A relative path to a file somewhere on the file system.
* `classpath:myprops.properties` - A file at the root of the classpath, for example `src/test/resources/myprops.properties`.
* `myprops.properties` - Looked up at the root of the classpath first, then next to the test class in the test's package.

A property source that cannot be found, or whose file extension no property source loader handles, is skipped, and a warning naming it is logged.
