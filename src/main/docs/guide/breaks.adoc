= Micronaut Test 5.3 Breaking Changes

=== `rebuildContext = true` no longer starts a second context for the first test
The context started for the class now serves the first test, so `@Context` beans no longer run twice before any test. Every later test still gets a new context, and a first test with method-level `@Property` values still gets its own.

The class context is built before the class's own setup, such as a `@BeforeAll` method or Spock's `setupSpec`. Anything that setup publishes for the context, for example a system property or the URL of a container it starts, is therefore no longer visible to the first test. Provide such values through `TestPropertyProvider`, which is resolved before the class context is built (with JUnit 5 this requires `@TestInstance(TestInstance.Lifecycle.PER_CLASS)`).

Conversely, changes that setup makes to beans of the class context, for example in a `@BeforeAll` method of a `PER_CLASS` test, are now visible to the first test, while every later test starts from a new context.

= Kotest 5 → 6 Breaking Changes

=== `TestName.testName` removed
In Kotest 5, the test name was accessed via `testCase.name.testName`.
In Kotest 6, `TestName` no longer has a `testName` property — it was replaced by `name`.

.Before
[source,kotlin]
----
testCase.name.testName
----

.After
[source,kotlin]
----
testCase.name.name
----

---

=== `TestResult` moved to `io.kotest.engine.test`
In Kotest 5, `TestResult` was imported from `io.kotest.core.test`.
In Kotest 6, it lives in `io.kotest.engine.test`.

.Before
[source,kotlin]
----
import io.kotest.core.test.TestResult
----

.After
[source,kotlin]
----
import io.kotest.engine.test.TestResult
----

---

=== Table-driven testing requires new dependency
In Kotest 5, `io.kotest.data.blocking.forAll` and `io.kotest.data.row` were included in the core framework.
In Kotest 6, they were extracted into a separate artifact.

.Add to build.gradle.kts
[source,kotlin]
----
testImplementation("io.kotest:kotest-assertions-table:<kotest6-version>")
----

.Imports remain the same
[source,kotlin]
----
import io.kotest.data.blocking.forAll
import io.kotest.data.row
----

---

=== `AbstractProjectConfig.extensions()` changed from function to property
In Kotest 5, extensions were registered by overriding a function.
In Kotest 6, `extensions` is a `val` property.

.Before
[source,kotlin]
----
override fun extensions() = listOf(MicronautKotest5Extension)
----

.After
[source,kotlin]
----
override val extensions = listOf(MicronautKotest5Extension)
----

=== JUnit Runner artifact renamed
In Kotest 5, the JUnit 5 runner artifact was:

[source,kotlin]
----
testImplementation("io.kotest:kotest-runner-junit5-jvm:<kotest5-version>")
----

In Kotest 6, the runner artifact was renamed to align with the new major version:

[source,kotlin]
----
testImplementation("io.kotest:kotest-runner-junit6-jvm:<kotest6-version>")
----

Make sure to update your build configuration accordingly when upgrading.
